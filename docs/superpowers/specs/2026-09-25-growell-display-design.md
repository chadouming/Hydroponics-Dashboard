# Growell 1 display — ESPHome design

Date: 2026-09-25
Status: approved in conversation (sections 1–4); pending written-spec review

## Goal

Show the equivalent of the Home Assistant "Growell 1" card (a `stack-in-card` with a
needle gauge and four `mini-graph-card`s) on a Sunton **ESP32-8048S070** (7", 800×480,
ESP32-S3 N16R8), configured through **ESPHome Builder**.

**Success** = a glance at the panel tells the same story as the HA card: same thresholds
and colours, the same 24 h trend shape, live values.

## Decisions (made with the user)

| Topic | Decision |
|---|---|
| Orientation / layout | Landscape 800×480: gauge column on the left, 2×2 mini-graph tiles on the right |
| Graph history source | Board records live readings **and** backfills the last 24 h from HA's REST history API on every HA connection (long-lived token on the board) |
| Graph rendering | Custom-drawn LVGL canvases (threshold-coloured line with hard transitions + fade fill) |
| Deliverable | **One self-contained YAML** pasted into ESPHome Builder (C++ lives in lambdas / scripts) |
| Touch | Not used (display only) |
| Testing | `esphome config` + full `esphome compile` in the official Docker image; **no desktop preview** |

## Assumptions (not contradicted by the user)

- The 5 entities exist in HA and reach the board through the native API (`homeassistant` sensors):
  `sensor.growell_1_kpi_score`, `sensor.greenhouse_growell_1_ph`,
  `sensor.greenhouse_growell_1_conductivity_value`, `sensor.greenhouse_growell_1_orp_value`,
  `sensor.greenhouse_growell_1_temperature`. Entity ids are substitutions at the top of the file.
- Units: EC µS/cm, ORP mV, Temp °C, pH none, Health Index none (0–100).
- Decimals: pH 2, EC 0, ORP 0, Temp 1, Health Index 0.
- `ha_url` is reachable from the board (plain local `http://…:8123` recommended; HTTPS with a public
  cert also works because `verify_ssl` uses the ESP-IDF CA bundle; self-signed HTTPS does not).

## Target platform facts (researched, ESPHome 2026.9.0)

- ESPHome 2026.9.0 is current; LVGL is **9.5** (since 2026.4.0). `meter` still exists (emulated on
  `lv_scale`, integer values); there is **no chart widget**; `canvas` exists and raw LVGL 9 draw
  calls (`lv_canvas_init_layer` / `lv_draw_line` / `lv_canvas_finish_layer`) work from lambdas.
- `mipi_rgb` has a board preset `model: ESP32-8048S070` (since 2026.5.0): all pins/timings,
  12.5 MHz pclk, requires `psram:`. No backlight in the preset.
- `http_request` runs on the main loop (blocking). With `capture_response: false`, `on_response`
  receives the unread `std::shared_ptr<HttpContainer> response`, so a lambda can stream the body
  with `response->read()` in small chunks.
- HA `GET /api/history/period?filter_entity_id=<id>&minimal_response&no_attributes` returns the last
  24 h (default window) as `[[{full first state}, {"state":"…","last_changed":"…"}, …]]`,
  including the state in effect at the window start.

## 1. File and hardware

Single file `growell-display.yaml`, pasted unchanged. User-supplied values come from Builder's
secrets: `wifi_ssid`, `wifi_password`, `growell_api_key` (the API encryption key generated by
Builder's new-device wizard), `ha_url`, `ha_token`.

- `esphome:` `min_version: 2026.5.0`.
- `esp32:` `variant: esp32s3`, `flash_size: 16MB`, `framework: esp-idf` with
  `advanced: execute_from_psram: true` and sdkconfig `CONFIG_ESP32S3_DATA_CACHE_64KB: y`,
  `CONFIG_ESP32S3_DATA_CACHE_LINE_64B: y` (prevents image drift during Wi-Fi/flash activity).
- `psram:` `mode: octal`, `speed: 80MHz`.
- `logger:` `hardware_uart: UART0` (USB goes through a CH340 on UART0).
- `display:` `mipi_rgb`, `model: ESP32-8048S070`, `update_interval: never` (LVGL drives it).
- Backlight: `ledc` on GPIO2 (1220 Hz) → `monochromatic` light "Backlight", `ALWAYS_ON`,
  exposed to HA. This is the only entity the board exposes.
- `api` (encryption), `ota` (esphome), `wifi`, `time: homeassistant`.
- `http_request:` `timeout: 10s` (history queries can be slow).
- Sensors: 5 × `homeassistant` sensors, `internal: true`.
- The user's HA token should belong to a dedicated **non-admin** HA user (limits blast radius).

## 3. Data flow

**Per-graph store** (globals, index i = 0 pH, 1 EC, 2 ORP, 3 Temp):
`sum[i][48]`, `cnt[i][48]` (slot 47 = newest), `head[i]` (absolute half-hour number
`floor(epoch/1800)` of slot 47; 0 = not started), `carry[i]` (value in effect before slot 0; NaN
if unknown).

- **Advance(i, h)**: if `head` is 0 → set to h. If h > head: the oldest `d = h − head` slots
  drop out; the newest non-empty dropped slot's mean becomes `carry`; shift and clear.
  (d ≥ 48 → carry = newest known value, clear all.)
- **Points for drawing**: walk slots 0→47 starting from `carry`; a slot with readings yields its
  mean and becomes the new carry; an empty slot repeats the carry; NaN carry → blank.
- **Live reading** (homeassistant `on_value`, finite values only, clock valid): Advance to now,
  add to slot 47, redraw that graph; always update the value label text/colour (even without a
  valid clock).
- **Minute tick**: Advance all graphs to the current half-hour; redraw those whose head moved.
- **Health Index**: `on_value` → needle + label (NaN → "—", needle hidden).
- **Backfill**: triggered each time Home Assistant (an API client subscribed to entity states,
  `api_server->is_connected(true)`) connects: boot, HA restart, Wi-Fi drop. It starts 3 s after
  the connection and only once the clock is valid. For each graph whose
  backfill hasn't succeeded on this connection: `GET {ha_url}/api/history/period?filter_entity_id=
  <entity>&minimal_response&no_attributes` with `Authorization: Bearer {ha_token}`.
  - Status ≠ 200 → log (401/403 → "check ha_token"), leave data untouched.
  - Status 200 → stream the body 512 bytes at a time through a small state machine that captures
    each `"state":"…"` and the following `"last_changed":"…"`; parse the number (`strtof`, finite
    only) and the ISO-8601 timestamp (fraction ignored, offset honoured).
  - Samples accumulate into **temporary** slots aligned to the current half-hour (older than
    slot 0 → temp carry, the latest wins; newer than now → slot 47). On a complete read the
    temporary store replaces the graph's store, the success bit is set, and the graph is redrawn.
    Incomplete read → discard, retry later.
  - A 5-minute interval retries graphs whose backfill hasn't succeeded while HA is connected.

## 4. Rendering (per graph canvas, W 207 × H 105, pad 3 px top/bottom)

1. Compute the 48 points; y-range = min/max of non-blank points; if the range is ~0, centre
   the line (±0.5). `yv(v) = pad + (max − v)/(max − min)·(H − 2·pad)`; `x_k = k·(W−1)/47`.
2. Fill the canvas with the tile colour.
3. **Fade fill**: for each column x on a segment whose two endpoints are non-blank, interpolate v,
   `y0 = round(yv(v))`; for y in y0…H−1: colour = band(value at y), alpha =
   `0.4·(1 − 0.85·y/H)`, blended over the tile colour and written straight into the RGB565 buffer
   (fallback `lv_canvas_set_px` if the buffer format isn't RGB565). Invalidate once.
4. **Line**: for each segment with non-blank endpoints, split at every threshold crossing and draw
   each piece with `lv_draw_line` (width 3, round caps, anti-aliased) in the band colour of the
   piece's midpoint, inside one `lv_canvas_init_layer` / `lv_canvas_finish_layer` pass.
   An isolated point is drawn as a 3 px dot.

Differences from mini-graph-card (accepted): half-hours aligned to the clock rather than
rolling from "now"; graph area taller than the card's 72 px.

## 5. Error handling

| Situation | Behaviour |
|---|---|
| Sensor unavailable/unknown | Tile value "—" grey; graph keeps history, nothing recorded |
| Health Index unavailable | Value "—", needle hidden |
| HA disconnected | Values freeze; amber "Home Assistant disconnected" note shown; reconnect → backfill |
| Backfill network error / timeout / truncated body | Keep current data, log warning, retry every 5 min |
| Backfill 401/403 | Log "check ha_token", retry every 5 min |
| Clock not yet valid | Labels update; nothing recorded; backfill waits for `time.has_time` |
| Malformed samples | Skipped individually |

## 6. Testing

1. `esphome config growell-display.yaml` in `ghcr.io/esphome/esphome:2026.9.0` (Docker) with a
   local test `secrets.yaml` (dummy values).
2. `esphome compile growell-display.yaml` in the same image (catches all C++/lambda errors).
3. Lightweight logic check, **only if the image already contains a host C++ compiler** (no extra
   downloads): the parser/bucketing block is delimited by marker comments in the YAML; a script
   extracts it verbatim and compiles it with a small test program (chunk-boundary splits,
   unavailable states, offsets, window edges, carry-forward).
4. On-device checklist for the user: stable image, values match HA, graphs full after reboot,
   Backlight light works in HA, disconnected note appears when HA is stopped.

## 7. User setup (documented in the YAML header and the final hand-off)

1. HA: create a non-admin user for the display, log in as it, create a long-lived access token.
2. Builder: New device → ESP32-S3 → skip install → Edit → copy the generated API encryption key.
3. Builder Secrets: add `growell_api_key` (that key), `ha_url`, `ha_token` (plus
   `wifi_ssid`/`wifi_password` if missing).
4. Replace the device's YAML with this file → Install (first time over USB).

## Out of scope

Touch interaction, backlight schedules/automations (possible from HA via the Backlight light),
multiple pages, persistence of history to flash (backfill makes it redundant), desktop preview.
